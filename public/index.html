01 / THE FEEDBACK LOOP

Don’t stop at
“it should work.”

From a design implementation to a tricky bug, give the agent a way to check the running UI.

  1. 01

    Capture the page and inspect its state.

  3. 03

    Keep going

Your agent decides when the goal is met. Browsershot provides the evidence.

02 / THE TOOLKIT

More context.
Better next steps.

Visual feedback is only the beginning. Bring the surrounding browser context into the same workflow.

  • 01 / VIEW

    Pages or elements

    Capture the whole page or a specific visible element.

    --full-page · --element
  • 02 / INTERACT

    Real UI states

    Wait, click, type, hover, or press before capture.

    --expect-element · --act
  • 03 / INSPECT

    State, not guesses

    Inspect elements and attributes. Return results as JSON.

    --inspect · --json
  • 04 / DEBUG

    See what failed

    Optionally collect console exceptions and network activity.

    --with-errors · --with-api
  • 05 / COMPONENTS

    Capture from the catalog

    Find and capture named Storybook or Ladle examples.

    library list · library refresh
  • 06 / REUSE

    Come back to a state

    Save pages and defaults. Add authentication when needed.

    page · config · --auth

Library catalogs are cached; refresh them when examples change.
